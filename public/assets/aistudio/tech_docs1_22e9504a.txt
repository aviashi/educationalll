# 1. PROJECT INTRODUCTION

## 1.1 Project Background

Web App Pengenalan Peralatan Listrik merupakan media pembelajaran digital untuk mata pelajaran Perbaikan Peralatan Listrik.

Aplikasi dirancang untuk membantu peserta didik memperoleh informasi mengenai berbagai peralatan listrik melalui media digital yang mudah diakses, memiliki visual menarik, serta menyajikan informasi secara terstruktur.

Website akan digunakan sebagai sarana pengenalan peralatan listrik dalam kegiatan pembelajaran.

## 1.2 Project Objectives

1. Menyediakan media pengenalan peralatan listrik berbasis web.
2. Membantu peserta didik mengenali bentuk dan nama peralatan listrik.
3. Menyajikan informasi mengenai fungsi, komponen, karakteristik, dan prinsip kerja peralatan.
4. Meningkatkan kemudahan akses terhadap materi pembelajaran.
5. Menghadirkan pengalaman belajar digital yang intuitif dan menarik.

## 1.3 Core Problem

Materi pengenalan peralatan listrik membutuhkan visualisasi dan informasi yang jelas agar peserta didik dapat menghubungkan nama, bentuk fisik, fungsi, dan karakteristik setiap peralatan.

Media digital ini ditujukan untuk membantu proses tersebut melalui katalog dan halaman informasi yang terorganisasi.

# 5. RESPONSIVE DESIGN SPECIFICATION

Pendekatan utama: Mobile-First Responsive Design.

Responsive behavior harus dirancang berdasarkan kebutuhan perangkat, bukan sekadar scaling ukuran.

## 5.1 Desktop

Target awal: 1024px ke atas.

Karakteristik:
- Sidebar navigation.
- Main content.
- Header.
- Grid katalog.
- Search interface.
- Hover interactions.
- Ruang konten yang luas.

## 5.2 Tablet

Target awal: 768px–1023px.

Karakteristik:
- Sidebar collapsed atau drawer.
- Grid menyesuaikan lebar.
- Spacing adaptif.
- Typography menyesuaikan.
- Navigasi tetap mudah diakses.

## 5.3 Mobile

Target awal: di bawah 768px.

Karakteristik:
- Single-column atau two-column layout sesuai ruang.
- Bottom navigation atau navigation drawer.
- Touch-friendly controls.
- Vertical information layout.
- Tidak ada horizontal overflow.
- Informasi tetap mudah dibaca.
- Navigasi mudah dijangkau ibu jari.

## 5.4 Responsive Principles

1. Gunakan CSS Grid dan Flexbox.
2. Gunakan responsive breakpoints.
3. Gunakan fluid typography bila diperlukan.
4. Hindari fixed-width layout.
5. Gunakan max-width untuk konten.
6. Pastikan gambar menyesuaikan container.
7. Pastikan seluruh elemen dapat digunakan melalui touchscreen.
8. Uji pada ukuran layar kecil, bukan hanya perangkat flagship.

Breakpoint awal dapat menggunakan:
- 640px.
- 768px.
- 1024px.
- 1280px.

Breakpoint dapat disesuaikan berdasarkan kebutuhan komponen.

# 6. ANIMATION & MOTION DESIGN

Animasi mengadopsi karakter desktop Linux modern.

## 6.1 Animation Types

- Page transitions.
- Fade-in.
- Slide transitions.
- Sidebar expansion.
- Drawer transitions.
- Card hover.
- Button feedback.
- Modal transitions.
- Skeleton loading.

## 6.2 Motion Principles

- Smooth.
- Natural.
- Subtle.
- Purposeful.
- Non-disruptive.

## 6.3 Timing Guidelines

- Micro-interactions: 150–250ms.
- Component transitions: 200–350ms.
- Larger transitions: 300–450ms.

Gunakan easing yang natural dan hindari animasi berlebihan.

Implementasikan prefers-reduced-motion.

Animation tidak boleh menghambat aksesibilitas atau performa.

# 9. DATA ARCHITECTURE

Informasi peralatan harus dipisahkan dari komponen presentasi.

Gunakan struktur data TypeScript.

Contoh konseptual:

interface Equipment {
  id: string;
  name: string;
  category: string;
  image: string;
  shortDescription: string;
  definition: string;
  functions: string[];
  components: {
    name: string;
    description: string;
    image?: string;
  }[];
  workingPrinciple: string;
  characteristics: string[];
  additionalInformation?: string;
}

Data final harus disesuaikan dengan kebutuhan materi.

Ketentuan:
- Setiap peralatan memiliki ID unik.
- Gunakan nama file gambar yang konsisten.
- Informasi harus dapat diverifikasi.
- Jangan mengisi informasi teknis berdasarkan asumsi.
- Komponen yang tidak relevan boleh dikosongkan atau disesuaikan.
- Hindari memaksakan format informasi yang sama apabila karakteristik peralatan berbeda.

# 10. ROUTING STRATEGY

Gunakan React Router.

Rute konseptual:

/                  → Home
/catalog           → Equipment Catalog
/equipment/:id     → Equipment Detail

Pastikan URL dapat digunakan untuk navigasi langsung.

## GitHub Pages Considerations

Karena aplikasi menggunakan GitHub Pages:

- Atur base path Vite sesuai nama repository.
- Pastikan asset paths benar.
- Perhatikan konfigurasi React Router.
- Gunakan strategi routing yang kompatibel dengan static hosting.
- Pastikan refresh pada halaman detail tidak menghasilkan 404.
- Uji URL deployment secara langsung.

Hash-based routing dapat digunakan jika dibutuhkan untuk menghindari masalah fallback pada GitHub Pages.
